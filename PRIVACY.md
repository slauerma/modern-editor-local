# Privacy and local data

Editing, compilation preparation, saved comments, version comparison, PDF reading/search, Help, setup checks, and reference previews run locally. AI review, discussion, the requested Changes PDF agent, preamble assistance, conversion of outside feedback, and explicitly requested help with compilation inputs send text through your configured Codex service.

## Local storage

Opening and editing documents can create `.modern-editor/documents/<document-id>/` beside the `.tex` or `.txt` file. This holds review comments and discussions, paper instructions, recovery drafts, source backups and version records, baselines (including the current session's opening checkpoint), reading state, and raw/converted outside feedback. These records can contain manuscript text, third-party feedback, and file identities. Existing legacy `.modern-editor` records may also be retained.

Application state, managed samples, compiler snapshots, PDFs, logs, executable settings, remembered reference locations, recent-project paths and opening times, saved pasted-context text, and **Sources used** records live outside the checkout in the application data location. **Settings → Storage and supported Codex version** shows the exact folder. These files can contain source text and absolute local paths. Old `.runtime/` copies are preserved after migration and can still contain the same material. The Codex CLI manages its own account configuration separately.

Text-encoding import is local and makes no model request. It previews supported encodings and writes a new UTF-8 copy at the chosen location; the original is not overwritten. The recent-project list stores up to 30 opened paths locally and restores the selected paper’s existing records. It does not search the computer for other papers.

**New drafts use the `.tex` or `.txt` location you choose outside the checkout.** Managed samples are real paper copies in application storage. **Export source…** creates a source-only file at a new path, without switching the open document or copying its comments, bibliography, figures, or history. Open the exported file to continue there.

Automatic recovery stores unsaved text separately from ordinary Save. Retained source versions also differ from the session-only Undo history. **Recover source…** lets you inspect readable versions and export a selected source to a new file, preserving originals. See the [recovery and storage FAQ](docs/FAQ.md#how-do-i-recover-after-a-crash-or-an-external-edit) before reloading or cleaning up data.

Keep personal papers outside the editor checkout. Sharing a paper folder can also share its hidden recovery and discussion records; inspect the files before sharing.

**Settings → Copy setup details** runs local version checks and writes a fixed summary to the clipboard: editor version, operating system version, Codex and TeX versions, and check status. It copies parsed version numbers rather than raw executable output and excludes manuscript text, file paths, account details and failure diagnostics. The button makes no Codex request; the copied summary is also available to inspect in Settings.

## Codex requests

**Reviews keep one active Codex conversation per paper.** Continue resumes it; Fresh starts another without deleting earlier records. ME saves questions, prepared prompts, responses and draft hashes in its application storage under `review-conversations/`, keyed by the opened file's full path. The Codex CLI also retains its own conversation history in its normal local storage. These records can contain complete passages and reference excerpts even when optional debug recording is off. Inspect them through **Review → More options → Review history**. Moving or renaming a paper starts a separate conversation.

Each review request identifies its scope and a frozen source snapshot. Source, saved instructions, decisions and history are read through tools rather than copied into the initial prompt. Ordinary comment discussions use the active review conversation; quick editorial actions remain independent. Completed paper Side Chat exchanges may be copied into the active review as notes for later requests. Clearing Side Chat does not remove those review-history copies. Optional rejection reasons remain in the comment records and can accompany future reviews. They become standing paper instructions only when you explicitly copy, inspect and save them.

**Project-folder reading is on by default.** Opening a paper authorizes ME’s ordinary Codex reviews and discussions to read supported documents from that file’s folder and subfolders when requested. The visible **Codex can read this folder** checkbox can disable this automatic folder access and is remembered per paper in app-owned storage. It does not modify the global Codex configuration. Imported manuscript sidecars cannot set this preference or choose another folder. The full frozen editor draft remains readable, including unsaved edits; Quick explanation and Quick alternative can read local draft/context views but cannot browse other folders or join the active review conversation.

This is read-only, on-demand access, not an automatic upload of all folder contents. Returned excerpts leave the machine through the configured Codex service. The reader supports TeX, bibliography/style files, ordinary text/data formats and extracted PDF text. Hidden/private-name files, generated directories and symbolic links are excluded; images and other binary files are not read. Limits and incomplete coverage are disclosed. The reader never follows a project link into an ungranted folder. Explicitly attached external references remain separately controlled. Turning the folder setting off revokes active reading sessions; it cannot erase excerpts already sent or retained in earlier records. Side Chat’s extra-reading switch defaults on for paper chats and can be turned off for an individual conversation in the current window. Editor-only help excludes automatic paper reading.

**Codex Side Chat** saves questions, replies, included context and screenshots in application storage, separately for editor help and each document path. It can therefore contain manuscript text, errors, visible account details, or private material shown in an image. **Suggest edits** uses Sol with Low effort and Fast speed, reading the selected source scope, saved discussion and paper instructions on demand. Enabled reading tools remain available on demand; editor Help and build diagnostics are omitted. Each received batch is saved in the paper's review results before automatic addition to Comments. Only accepting a suggestion changes the draft. **Clear chat…** removes the selected conversation. Clearing it does not undo content already sent to the configured service, remove comments or batches created from replies, or clear the separate **Sources used** records.

Sending a Codex Side Chat question includes the installed version, your request, source scope and selected diagnostics/comment. Bundled guides, saved exchanges, paper instructions and selected source are available through reading tools. Paper source, current comment, error/build details and read-only reference access have separate controls. Editor-only help excludes automatic paper source and references; screenshots and error details you explicitly include can still contain paper information. Attached PNG/JPEG images are decoded and re-encoded locally to drop metadata, then sent as image inputs to Codex. Visible image content is preserved. Previous images are retained locally but are not automatically resent. Inspect **Preview what is sent** and the thumbnails before sending. Chat itself cannot edit files or run repairs. A reply can contain several suggestions; adding one or all of them creates review comments without applying edits. Each revision still needs acceptance. Follow-ups can search and page through saved exchanges in `chat-history.md`; **Discuss this** puts the chosen suggestion’s exact wording at the top of that view. With extra reading off, the reader exposes only the chosen source scope, not the rest of a selected-passage document.

AI actions launch the editor-managed Codex CLI (pinned to 0.163.0), or a custom executable explicitly chosen in Settings, with your existing Codex sign-in. The managed binary is installed by npm; credentials and account configuration remain in Codex’s normal storage, outside the source dependency tree. The editor does not auto-update the CLI or modify your global/desktop installation. Settings can select a model for editor requests or retain the CLI’s configured default; the choice is saved locally without changing the CLI’s own settings. Side Chat has separate Model, Effort and Speed controls; its **Editor default** model choice follows Settings. **Load models / Refresh models** reads the CLI’s catalog without sending manuscript text or starting a model turn. Submitted text can leave the machine through that service. The editor sends structured text according to the action:

- A review prompt includes the author’s request, exact scope, format guidance and context identifiers. `current-draft` contains the frozen unsaved buffer. `paper-instructions.md` and `review-decisions.md` expose existing saved preferences and decisions on demand.
- A discussion prompt includes the selected comment, current proposal, existing wording choices and author reply. Draft context, saved instructions and comment history are read separately.
- Preamble assistance reads the current root snapshot; its prompt includes placement metadata and, when retrying, the previous attempt and compiler output.
- Outside-feedback conversion identifies the feedback and any batch item IDs, then reads the feedback, saved instructions and captured source through local tools. The raw feedback and source snapshot are saved before the request, including when conversion fails. A resumed conversion uses that saved snapshot.
- Reviews and discussions can consult the current draft, enabled project folder and enabled reference files and folders using bounded, read-only list/search/read tools. Returned display names, excerpts, page/line ranges and coverage notices go to Codex. Optional manually previewed excerpts are readable as `selected-context.md`.
- **Ask Codex to help** with compilation inputs sends the locally prepared preview: source excerpts, relative file inventory and dependency-check results. It proposes a file list without running LaTeX or changing source.

The context preview shows the short initial request and scope. Before sending, ME adds the available context identifiers and active conversation identity. The readable Markdown documents are views of existing records, not new files or a separate memory system. Review history has a searchable index and individual exchanges without old prompts/drafts prepended to answers. Continue also retains runtime history; the preview is not a full transcript of that history. **Review history** exposes saved exchanges and their prepared prompts. The external Codex runtime may also add its own configuration or model metadata. Attaching references makes no model request. Additional reference locations are remembered for this paper; later reviews and discussions may read relevant excerpts without another file-by-file preview. **Sources used** records returned excerpts and search coverage after each request. Disable or remove a location to exclude it from future requests. Optional exact-excerpt selections remain available and require their own preview.

This avoids manual upload management, but content returned to Codex leaves the computer through that service. Reading tools use opaque IDs rather than arbitrary paths and omit absolute root paths from their metadata; source text itself can contain identifying information. The current unsaved draft is authoritative. References cannot be edited by these tools. Missing or changed locations produce notices or stop the read. Root permissions are stored by the app, not accepted from a paper's imported sidecars.

Codex responses, including rejected responses, may be retained in the document's local review records so completed work is recoverable. Removing a reference does not delete its local file or erase content already included in an earlier request or answer.

**Settings → Data & cleanup** can archive and clear old owned builds or selected papers' ME records after a file-by-file preview. The open paper, source files, exports, global settings and sign-in are protected. The dated recovery archive retains the cleared data; shared diagnostics, usage, recent-file shortcuts and Codex CLI storage are kept separately. This does not erase requests already sent to the service. See [Data & cleanup](docs/USER_GUIDE.md#data--cleanup) for the exact scope.

Direct JSON comment import is local and makes no model request. It retains the imported comments in the paper’s review records without applying their edits. Importing outside prose feedback with Codex is a separate action.

Review scope is the opened root source or selection; included source files are not expanded automatically. **Save note** stores a discussion note locally without contacting Codex. Saved notes can be included as context when you later explicitly ask Codex about that comment; inspect **Preview request** before sending. The [user guide](docs/USER_GUIDE.md) explains how to preview context and distinguish local actions from AI requests.

Before sending paper text, the client checks the CLI version and reads its effective configuration, including trusted project configuration. It disables each configured MCP server explicitly in the new task, then checks the task's complete MCP inventory: every expected server must report disabled, with no tools or resources. Missing, unexpected, active, or uncheckable entries stop the request before paper text is sent.

This policy is currently verified for **Codex CLI 0.153.4**, **0.154.0-alpha.6.2**, **0.155.0-alpha.2.6**, **0.155.0-alpha.9.2**, **0.160.1** and **0.163.0**. Other versions stop before an AI request until their compatibility is tested and the supported-version list is deliberately updated. The [real configuration probe](TESTING.md#real-codex-configuration-check--no-account-request) exercises the same client against harmless inherited MCP servers, without sending a model request or copying account credentials.

The client also checks its configured restrictions on web search, shell execution, plugins, apps, host instruction discovery, goal tools (where supported) and other tool features. Every task is read-only with approvals disabled. Review conversations are persistent; other actions use ephemeral tasks. Restrictions are reapplied and checked before each resumed request. Only the editor's registered reference callbacks, bounded active-conversation history reader and review batch publisher are accepted as dynamic tools, matched to the current thread and turn. The publisher validates and saves comments locally; it cannot edit or accept source changes. CLI 0.163.0 also exposes built-in MCP resource functions; with inherited servers disabled, the tested inventory is empty and reads from disabled servers are refused. Automatic CLI model routing is disabled so explicit model choices remain authoritative. Current file grants still apply; disabling access cannot erase earlier excerpts from an existing conversation. Other tool/permission callbacks are rejected. These are CLI configuration controls, not proof of a complete empty built-in tool catalog or an operating-system sandbox. Configuration reading and task creation/resumption are separate operations: a concurrent local configuration change could start a newly added integration before the inventory check refuses the task. These controls do not alter the service's account data policies, and the editor does not rewrite your Codex configuration.

## Compilation

LaTeX runs locally on a copied paper snapshot, with shell escape and user `latexmk` startup files disabled. The snapshot can include local bibliography, graphics, and font resources from the paper folder. The application checks recorded dependencies before treating a compile as suitable for checked acceptance. TeX runs as the local user, so these checks are not a filesystem isolation boundary; compile documents you trust.

Above **50 MB or 500 files**, the editor starts local dependency discovery to leave unrelated files out of the snapshot. The cap on actual required inputs is **200 MB / 2,000 files**, including explicit file selections. Local graphic alternatives are copied together so TeX can use its normal lookup order. Other ambiguous references require a deliberate file choice; Codex assistance starts only through **Ask Codex to help**. Proposed paths are checked within the paper folder. A PDF with unresolved dependency commands remains unverified and cannot authorize checked acceptance.

Changes PDF typesetting and its source-change journal run locally. The journal can contain removed passages, accepted replacements and explanations. Opening **Changes PDF** requests GPT-6.1 Sol arrangement of those changed blocks and reasons, then further updates after the configured acceptance count, Save or Refresh while open. The agent may request up to three rendered comparison pages as image inputs. Those images contain earlier and current paper text and go to Codex for presentation review; unrelated editor screenshots are not included. No reference-folder reading or file-editing tools are enabled. Closing the view or Pause/Stop stops its updates. Exact source reconstruction and supported layouts remain checked by ordinary code.

**PDF review mode** prepares Original, Proposed revision and Changes locally. Its routine updates make no model request. **Refine comparison with Sol** explicitly uses the arrangement and optional page-image check described above; discussion and alternative buttons remain separate AI requests. The PDF session shares ordinary paper records and recovery. Exported PDFs or comparison LaTeX can contain tentative suggestions and deleted text; generated LaTeX is saved to a new file and still needs the paper's resources.

## Optional debug records

Detailed debugging is **off by default**. If enabled in Settings, the separate `debugging/` folder in application storage records submitted prompts, replies (including malformed replies), request errors, input screenshots, save/build events, bounded interaction metadata (such as comment navigation, acceptance and discussion), operation timings and optional periodic screenshots of this editor's visible window. No desktop or other application capture is performed. Records may contain manuscript text, private instructions, paths or sensitive material visible in the editor. Individual keystrokes are not recorded. The CLI's environment, authentication files and transport configuration are not logged.

These files are used only for debugging: the editor never reads them into paper context, reviews, comparison generation or recovery, and does not upload them. `register.json` lists each payload, type, date and size. Small action/timing events are grouped into files of up to 100 timestamped events. **Settings → Debugging** shows the register and offers individual deletion, folder inspection and deletion of all records (which also switches logging off). The 200 MB / 500-record limit stops further logging rather than silently deleting evidence. Logging errors do not prevent normal editing. Deleting local debug records does not delete content already submitted by an AI request, ordinary recovery/sidecar records, or the separate compiler cache.

## Local usage metadata

**Usage & speed** records metadata by default, independently of optional rich debugging: request ID/time, a hash of the open paper path, purpose, model, effort, speed, outcome, elapsed/first-batch/first-answer/setup times and token counts when supplied. It retains the most recent 1,000 requests in application storage under `usage/requests.json`. It does not store source, prompts, replies, screenshots, raw paper paths or authentication data, and is not included in model context or automatically uploaded. Disable future recording in the panel; existing records remain. Recording failure does not stop editing or a Codex reply.

**Refresh account limits** makes a read-only request through the installed Codex CLI and existing account sign-in. It starts no model turn and sends no manuscript. The editor displays available allowance/reset windows and the checked time, without saving account identifiers, balances or credentials to usage history. These are account-wide figures, separate from local request totals.

## Pasted context, guidance and PDF export

Pasted context is stored verbatim in the application data references folder and attached only to its paper. Saving, inspecting, copying, renaming, disabling or removing it makes no AI request. Enabled documents are available to later requested paper reviews and discussions through the same bounded reading tools as file references. Side Chat includes references only when its reference option is selected. Disabling prevents future reads; removing pasted context deletes the saved copy. These actions do not delete excerpts already retained in Sources used, chat, debug records or a request sent to Codex.

Paper instructions and minimal-edit preferences are stored beside the paper and accompany paper reviews, comment discussions, feedback conversion and paper Side Chat. Editor-only help does not include them. Classic view changes only the presentation and saved layout.

Files & history shows local paths for discovering source, context, state and PDFs. Exporting a PDF writes the selected compiled snapshot to the user-selected destination; it does not call Codex, compile implicitly, accept edits or save the manuscript. A comparison or proposal PDF may reveal removed or tentative text. Choose the ordinary current-draft PDF when that is what you intend to share.

Saved wording choices and rejected suggestions stay in the paper’s local review files. New reviews can read the saved decisions to avoid repeating rejected suggestions. Quick alternative uses Sol with the selected comment and readable draft, paper guidance and discussion; other folders are unavailable. These actions remain user-initiated.
